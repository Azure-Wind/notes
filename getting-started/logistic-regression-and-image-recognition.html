01

任务与数据#

把 10 类识别收缩成「是不是 1」，是理解整套流水线最省力的入口：输入、模型、损失、梯度、更新、评估，每一环都能手算、能可视化、能被实测数字验证。

1.1 问题定义#

一张 28×28 的手写数字图，按行展开成 784 维列向量 x∈ℝ784，每个分量是 0～255 的灰度值。标签 y 只取两个值：y=1 表示「这是数字 1」，y=0 表示「这是数字 0」——直接沿用 MNIST 原始标签，不需要任何重编码。

模型要做的事只有一件：输出一个概率 y^=P(y=1|x)∈(0,1)。当 y^>0.5 时判为 1，否则判为 0。整份文档要回答的就是：这 785 个参数怎么从数据里学出来。

1.2 数据：为什么用 0 和 1#

MNIST 的训练集有 60,000 张、测试集 10,000 张，覆盖 0–9 十类。这里只保留标签为 0 或 1 的样本，训练集剩 12,665 张、测试集剩 2,115 张，其余八类整类丢弃。这不是为了偷懒，而是有意把问题压到「二分类」这个最小可解释单元。

形状差异最直观。0 是闭合的环，1 是一根竖笔，权重学成什么样一眼能看懂；换成 3 和 8，线性模型的行为就没这么容易解释了。

难度恰好合适。这两类在像素空间几乎线性可分，单层模型就能做到 99.9%，于是注意力可以全部放在「推导为什么成立」而不是「怎么调参」；同时它又保留了两张真正难分的样本（见 8.4 与 8.6），足够说明线性模型的边界。

类别几乎均衡（53% / 47%），准确率不会被多数类绑架，评价指标的含义最干净。

1.3 数据格式：IDX 的字节结构#

MNIST 用 IDX 格式存储，四个文件都是 gzip 压缩的裸字节流，没有表头、没有对齐填充。图像文件的头部 16 字节 = 4 字节魔数 + 4 字节样本数 + 4 字节行数 + 4 字节列数；标签文件只有 8 字节 = 4 字节魔数 + 4 字节样本数。魔数的低 16 位（0x03 / 0x01）其实就编码了维度数。

1.4 预处理管线#

从磁盘到模型输入一共七步，每一步都在代码里对应一行，没有任何隐藏操作：

*.gz4 个文件→ gzip.read()解压为 bytes→ frombufferuint8，零拷贝→ [16:] / [8:]跳过头部→ reshape(N, 784) 视图→ / 255.0归一化到 [0,1]→ 掩码 y∈{0,1}12,665 × 784 float32

有三处值得单独掂量，它们都会在后面变成真实的坑：

  • 归一化把像素压到 [0,1]。特征全部同尺度，梯度的量级就可预测，固定学习率 α = 0.1 才能一路用到底，不必为每个特征单独调步长。
  • 筛选用的是布尔掩码，而不是删除循环。掩码表达式 (y==0)|(y==1) 在 (N, 1) 的标签上直接使用会先被压平，这一点在第 7 章会展开。
  • 类型：矩阵用 float32（内存减半），标量 b 与累积量用 float64，避免 60 步迭代后误差可见地累积。

1.5 数据的三个统计事实#

第一，像素高度稀疏：绝大多数像素接近 0，真正有笔画的只有几十到一百多个点。这使 WTx 的计算虽然名义上是 784 次乘加，实际信息量集中在少数非零分量上。

第二，两类几乎线性可分：一个只有 785 个参数的线性模型把测试错误压到 2 张。这既是好消息（推导中的凸性、唯一最优解都能真正达到），也意味着它不能证明「逻辑回归很强」——它只证明「0 和 1 本来就好分」。

第三，训练集和测试集同分布：都来自同一批书写者、同一套扫描流程。所以这里直接拿测试集做最终评估是干净的；在真实项目里必须另切一份验证集，否则超参数（学习率、轮数、阈值）会悄悄过拟合到测试集上。

02

模型：从硬判决到概率#

感知机只回答「是 / 否」，逻辑回归回答「有多像」。这一章把两者之间的那一步——sigmoid——拆开看清楚。

2.1 硬判决的三个麻烦#

最早的感知机直接把内积的符号当类别：

y^={1，若 WTx+b>00，若 WTx+b≤0
(1)

这个式子在数学上很清楚，在优化上却没法用：

  • 不可导：判决在 0 处跳变，梯度要么是 0 要么不存在，梯度下降无从下手。
  • 没有置信度：只输出 0 或 1，分不清「非常像 1」和「勉强算 1」。
  • 对边界过敏：内积从 −0.001 变到 +0.001，输出就整个翻转，而这半个像素的差别本不该有意义。

解决办法不是换模型，而是保留判决前的那个数。把内积记作分数 z：

z=WTx+b
(2)

z 的符号给出类别，|z| 给出「有多确定」。现在只差一个把整条实轴压进 (0,1) 的单调函数，让输出可以被解释成概率。

2.2 sigmoid：把分数压成概率#

σ(z)=11+e−z
(3)

它有四个性质，每一个都在后面的推导里被用到：

σ(z)∈(0,1)σ(−z)=1−σ(z)σ′(z)=σ(z)(1−σ(z))
(4)

第三条尤其关键：sigmoid 的导数可以用它自己表示，不出现 e 的指数。这解释了为什么 σ′(0)=0.25 是整条曲线上的最大值——在两端，曲线被压平，导数迅速趋近于 0。这一点在第 6 章会变成交叉熵与均方误差的分水岭。

2.3 概率解释与对数几率#

把输出解释成条件概率 y^=P(y=1|x)，那么 1−y^ 就是 P(y=0|x)。把 sigmoid 反解，得到：

logy^1−y^=z=WTx+b
(5)

左边是对数几率（log-odds）：y^1−y^ 表示「是 1 与不是 1 的概率之比」，取对数后取值范围是整条实轴。这个等式说明模型做了一个非常具体的假设：对数几率是像素的线性函数。逻辑回归（logistic regression）的名字就来自这里——它并不是「对概率做线性回归」，而是「对对数几率做线性回归」。

令 y^=0.5，等价于 z=0，于是判决边界是：

WTx+b=0
(6)

在 784 维输入空间里它是一个超平面；在 28×28 的像素平面里，它把「像 1 的图」和「像 0 的图」分成两片。线性模型的全部表达能力，就压缩在这一个超平面上。

2.4 权重就是一张模板#

把 σ′(0)=0.25 放在一边，先看 z=WTx+b 的结构：W 的第 j 个分量，正好是第 j 个像素的投票权。把这个 784 维向量 reshape 回 28×28，就得到一张与输入同尺寸的「模板图」：正权重的像素越亮，越支持判为 1；负权重的像素越亮，越支持判为 0。

训练完成后（8.3 节）这张模板长这样：中间一条竖直的亮带，两侧偏蓝。换句话说，模型学到的是「中间有竖笔 → 1，两侧有笔画 → 0」。它不是记住了某几张图，而是把两类图像的平均差异提炼成了一个方向。

这也预告了它的失败模式：模型只能表达「哪个位置有笔画」，表达不了「笔画之间是否闭合」。一个写得很斜、几乎没有闭环的 0，会在这个模板下得到很高的分数——第 8.4 节的两张错图正是如此。

03

损失：从最大似然到交叉熵#

损失函数不是拍脑袋选的。把「模型输出是概率」这个前提用足，损失就被最大似然唯一地确定了。

3.1 单个样本的似然#

既然 y^ 是「是 1」的概率，那么一次伯努利试验的似然可以写成一个统一的形式，无论真实标签 y 取 0 还是 1：

L(θ)=y^y(1−y^)1−y
(7)

验证一下：y=1 时，第二项的指数是 0，整体等于 y^；y=0 时，第一项不起作用，整体等于 1−y^。一个式子覆盖了两种情形，这是后面能写成统一损失的前提。

假设样本独立同分布，整个数据集的似然是连乘：

L(W,b)=∏i=1Ny^iyi(1−y^i)1−yi
(8)

3.2 取负对数：交叉熵#

连乘在数值上会下溢（几千个小于 1 的数相乘），而且求导麻烦。取对数把乘变加，再取负号把「最大化似然」变成「最小化损失」——log 是单调函数，最优解不变：

ℓ(x,y)=−logP(y|x)=−[ylogy^+(1−y)log(1−y^)]
(9)

对所有 N 个样本取平均，得到训练目标：

J(W,b)=−1N∑i=1N[yilogy^i+(1−yi)log(1−y^i)]
(10)

这就是二元交叉熵（binary cross-entropy）。名字里的「交叉」来自信息论：它衡量的是用模型分布 q 去编码真实分布 p 所需的平均比特数。

3.3 为什么是它，而不是别的#

四个理由，前三个是数学上的，最后一个是工程上的：

  1. 最大似然：在「输出是伯努利参数」的假设下，最小化 BCE 等价于最大化似然，也等价于最小化模型分布与经验分布的 KL 散度。
  2. 凸：J(W,b) 对参数是凸函数（4.4 节给出 Hessian），所以梯度下降不会卡在局部最优，全零初始化也不会停在鞍点。
  3. 梯度干净：sigmoid 的导数会被损失里的分母精确约掉，最终梯度就是 y^−y——「预测减真实」，没有多余的因子。
  4. 概率可解释：输出直接当概率用，可以接阈值、接代价矩阵、接校准，不需要额外变换。
从 KL 散度看

交叉熵可以拆成「真实分布本身的熵」加「两个分布的 KL 散度」：

H(p,q)=H(p)+KL(p‖q)

第一项与模型参数无关，因此最小化交叉熵就是在最小化 KL 散度，也就是让模型分布尽量贴近真实分布。这一步不是类比，是恒等式。

3.4 数值实现：别让 log(0) 毁掉训练#

公式里 y^∈(0,1) 是开区间，但浮点数会把它推到闭区间的端点上：sigmoid 在 z=40 时输出就是 1.0，此时 log(1−y^) 会得到 −∞，一个样本就能把整批损失污染成 inf。

工程上有三种处理，代价依次降低：

  • 加 ε：把 log(ŷ) 写成 log(ŷ + 1e-8)。最简单，代价是给损失引入约 1e-8 的偏置，对这个量级的问题完全可以忽略。
  • 用 softplus 重写：利用 log σ(z) = −softplus(−z)，绕开「先算 ŷ 再取 log」的两次精度损失。
  • 交给框架：PyTorch 的 binary_cross_entropy_with_logits、TensorFlow 的 sigmoid_cross_entropy_with_logits 内部就是稳定版本。

04

形状与 W 相同：784 维
对分数
∂ℓ/∂z = ŷ − y
σ′ 被精确约掉

∂ℓ/∂ŷ = −y/ŷ + (1−y)/(1−ŷ)

注意反向格子里出现了一个漂亮的结果：经过 sigmoid 时那个容易爆掉的 ∂ℓ/∂ŷ 与 σ′ 相乘后，分母被完全抵消，只剩 y^−y。这不是巧合，而是「交叉熵 + sigmoid」这一对组合的代数必然。下面五步就是把它算出来。

4.2 五步推导（单个样本）#

第 1 步 · 损失对预测概率。交叉熵里只有一项在 y = 1 或 y = 0 时存活，直接求导：

∂ℓ∂y^=−yy^+1−y1−y^
(11)

第 2 步 · 概率对分数。sigmoid 的导数可以用它自己表示：

∂y^∂z=σ(z)(1−σ(z))=y^(1−y^)
(12)

第 3 步 · 链式相乘。把两步接起来，逐行化简：

∂ℓ∂z=(−yy^+1−y1−y^)y^(1−y^)=−y(1−y^)+(1−y)y^=−y+yy^+y^−yy^=y^−y
(13)

中间那步 yy^−yy^=0 是关键：两个交叉项正好抵消，什么都没剩下，除了「预测减真实」。

记住这个结果

∂ℓ∂z=y^−y

梯度就是「预测值减真实值」：预测高了，梯度为正，更新会把分数往下压；预测低了，梯度为负，往下抬。这个式子的符号与直觉完全一致，没有多余的因子 0.25 或 σ′——这正是交叉熵的功劳。

第 4 步 · 分数对参数。分数是参数的线性函数，导数就是输入本身：

∂z∂W=x,∂z∂b=1
(14)

第 5 步 · 合起来。再乘一次，得到最终梯度：

∂ℓ∂W=(y^−y)x,∂ℓ∂b=y^−y
(15)

形状上自洽：y^−y 是标量，x 是 784 维向量，所以 ∂ℓ∂W 是 784 维，与 W 同形——这正是梯度下降要求的前提。

4.3 从单样本到全体：矩阵形式#

上面的推导假设只有一个样本。数据集的损失是 N 个样本的平均，而求导是线性算子，平均的导数就是导数的平均：

∇WJ=1N∑i=1N(y^i−yi)xi=1NXT(y^−y)
(16)

最后一步把求和写成了矩阵乘法：把 N 个样本堆成矩阵 X∈ℝN×d，把 y^−y 堆成列向量，转置相乘就是在做「加权求和」。这一步是向量化的全部秘密，也是 NumPy 版本能一行算完梯度的原因。

这张表值得逐行核对。绝大多数「梯度算错了」的 bug，最后都能归结成某个张量的形状不对，而形状错误往往不会报错——NumPy 会愉快地广播出 (12665, 784) 这样的矩阵，然后训练照样跑，只是学不到东西。

4.4 凸性：为什么一定有最优解#

把 ∇WJ 再求一次导，得到 Hessian：

∇2J=1NXTSX,S=diag(y^i(1−y^i))
(17)

因为 0<y^<1，所以 S 的每个对角元都是正的，H=1NXTSX 就是一个半正定矩阵：对任意向量 v，vTHv=1N∑i=1Ny^i(1−y^i)(xiTv)2≥0。每一项都是「非负系数 × 平方」，所以损失曲面只能向上弯。

半正定意味着损失曲面是一个碗形的、只有一个底的曲面。再往前一步：如果 X 列满秩（这里 12665≫784，而且图像之间差异足够大），Hessian 就是正定的，最优解唯一。于是三件事同时成立：

  • 梯度下降不会停在局部最优，因为根本不存在局部最优；
  • 从任何初始点出发都会收敛到同一个解，初始化只影响路径、不影响终点；
  • 「训崩了」只可能是步长太大或实现有 bug，不会是优化问题本身的性质。
实测曲率

用幂迭代在本数据集的最优点处估计 Hessian 的最大特征值，得到 λmax≈0.638。在局部二次近似下，梯度下降的稳定步长上界是 α<2λmax≈3.13，这和实测「α 取到 1 仍然稳定收敛」是一致的。

4.5 为什么全零初始化在这里是安全的#

「不能全零初始化」是深度学习里流传很广的一条经验，但它有前提：多层网络、每层有多个隐藏单元。此时全零会让同一层的所有单元在每一步拿到完全相同的梯度、保持完全相同的值，它们永远学不到不同的特征——这叫对称性问题。

逻辑回归没有这个问题：它只有一个线性层，加一个逐元素的非线性，不存在「同一层里互相不同的单元」。再加上 4.4 节的凸性，W=0,b=0 同样能走到全局最优。而且全零初始化有个额外好处：初始 y^=0.5，初始损失恰好是 ln2≈0.693，一个可以手算核对的基准点（实测 0.693147）。

4.6 一个高频错误：多乘一次 σ′#

把「损失对 y^ 的导数」和「损失对 z 的导数」搞混，是初学这段推导最常见的失误。若误写成 ∂ℓ∂z=(y^−y)y^(1−y^)，训练仍然能跑，但每一步的有效步长被乘上了 y^(1−y^)——这个值最大只有 0.25，绝大多数时候更小，于是收敛会慢一个数量级以上，还很容易被误判成「学习率调小了」。

诊断方法很简单：拿一个样本手算。ŷ = 0.9、y = 1 时，正确梯度是 0.9 − 1 = −0.1；如果代码算出 −0.009，就是多乘了 σ′。

05

优化：梯度下降怎么走#

有了梯度，剩下的事只有一件：沿着负梯度走一步，再走一步。看起来简单，但步长、批量、停止条件每一个都会改变结果。

5.1 更新规则#

W←W−α1NXT(y^−y)b←b−α1N∑i=1N(y^i−yi)
(18)

两个式子是同一个意思：参数的更新量 = 学习率 × 平均梯度。负号来自「沿梯度反方向下降」，α 控制每步走多远。本项目取 α=0.1、走 60 步。

5.4 什么时候停#

损失从第 1 步的 0.438 一路降到第 60 步的 0.0312，看起来还有下降空间。但测试准确率在第 1 步就已经是 99.57%，后面的 59 步只把它抬到 99.91%。换言之：损失还在降，可准确率早就饱和了。

原因是交叉熵会继续把已经分对的样本推得更「自信」（ŷ 更接近 0 或 1），损失的下降主要来自这些样本的边际改善，而它们的类别标签本来就不会变。如果目标只是准确率，第 5 步之后的边际收益已经很小；如果下游要用概率做排序或阈值决策，多训几十步让概率更尖锐是有意义的。

所以停止条件不应该只看损失，而应该看验证集上的任务指标——这是工程与推导的一个分界点。

06

交叉熵 vs 均方误差#

同样是「预测和真实差多少」，两种损失给出的梯度却完全不同。这一章把差别算清楚，并给出实测对照。

6.1 均方误差的梯度长什么样#

若把损失换成均方误差 ℓ=12(y^−y)2，对分数求导要多走一步链式：

∂ℓ∂z=(y^−y)σ′(z)=(y^−y)y^(1−y^)
(19)

和 (13) 式对比，多出来的正是 y^(1−y^)。这个因子有两个后果，一个关于速度，一个关于形状。

6.2 后果一：自信地错，却几乎不更新#

取一个具体的坏样本：真实 y=0，模型却给出 y^=0.99。此时交叉熵的梯度是 0.99−0=0.99，而均方误差的梯度是 0.99×0.0099≈0.0098——相差约 100 倍。模型犯了最严重的错误，MSE 给出的修正信号却最弱。

更糟的是这个倍数随错误程度变化：y^ 越接近 0 或 1，σ′ 越小，梯度越接近 0。这就是「梯度消失」在单层模型里的样子——不是深层网络才有。

两种损失对「自信地错」的惩罚上限

当 y^→0 而 y=1 时：

交叉熵 −logy^→+∞，惩罚无上界；均方误差 120−12=0.5，最多罚 0.5。

「自信地错」在交叉熵下是灾难，在 MSE 下只是一个普通的小误差——这是两者最本质的区别。

6.3 后果二：损失曲面不再是凸的#

对 MSE 再求一次导，第二项可以为负：

∂2ℓ∂z2=σ′2+(y^−y)σ′(1−2y^)
(20)

代入 y^=0.9,y=0：第一项 0.092=0.0081，第二项 0.9×0.09×(1−1.8)=−0.0648，加起来是 −0.0567——负的。二阶导为负意味着曲面在这个方向上向下弯，凸性不成立。

交叉熵则没有这个问题：它的 Hessian 是 XTSX/N，永久半正定。「凸」不是审美偏好，它直接决定优化器会不会卡住。

一句话总结

交叉熵 = 对「概率」做最大似然，梯度是干净的 ŷ − y，曲面是凸的，对自信的错误惩罚无上界。

MSE + sigmoid = 对「数值」做最小二乘，梯度带一个 ≤ 0.25 的衰减因子，曲面非凸，对自信的错误只罚 0.5。

"""
逻辑回归：0 vs 1 手写数字分类（纯 NumPy 从零实现）

对应推导的步骤：
  1. 前向  z = W·x + b,  y_hat = sigmoid(z)
  2. 损失  J = -(1/N)·Σ [ y·ln(y_hat) + (1-y)·ln(1-y_hat) ]
  3. 梯度  dJ/dW = (1/N)·Σ (y_hat - y)·x,   dJ/db = (1/N)·Σ (y_hat - y)
  4. 更新  W ← W - lr·dW,  b ← b - lr·db
"""
import os
import gzip
import urllib.request

import numpy as np


def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-z))


def cross_entropy(y_hat, y):
    eps = 1e-8
    return -np.mean(y * np.log(y_hat + eps) + (1 - y) * np.log(1 - y_hat + eps))


def load_mnist(data_dir="data"):
    base = "https://ossci-datasets.s3.amazonaws.com/mnist/"
    # (文件名, 表头字节数, 样本数, 每样本维度)
    files = {
        "X_train": ("train-images-idx3-ubyte.gz", 16, 60000, 784),
        "y_train": ("train-labels-idx1-ubyte.gz", 8, 60000, 1),
        "X_test": ("t10k-images-idx3-ubyte.gz", 16, 10000, 784),
        "y_test": ("t10k-labels-idx1-ubyte.gz", 8, 10000, 1),
    }
    out = {}
    for key, (fname, header, n, dim) in files.items():
        path = os.path.join(data_dir, fname)
        if not os.path.exists(path):
            os.makedirs(data_dir, exist_ok=True)
            print(f"下载 {fname} ...")
            urllib.request.urlretrieve(base + fname, path)
        with gzip.open(path, "rb") as f:
            raw = np.frombuffer(f.read(), dtype=np.uint8)[header:]
        out[key] = raw.reshape(n, dim)
    return out["X_train"], out["y_train"], out["X_test"], out["y_test"]


def show_weights(W):
    w = W.reshape(28, 28)
    lo, hi = w.min(), w.max()
    w01 = (w - lo) / (hi - lo + 1e-8)
    ramp = " .:-=+*#%@"
    for row in w01:
        print("".join(ramp[int(v * (len(ramp) - 1))] for v in row))


def main():
    # ---------- 0. 加载数据 ----------
    X_train, y_train, X_test, y_test = load_mnist()

    X_train = X_train.astype(np.float32) / 255.0    # 灰度 [0,255] -> [0,1]
    X_test = X_test.astype(np.float32) / 255.0

    # 只保留数字 0 和 1（标签是 (n,1)，先压平成 (n,) 才能当布尔索引）
    mask_train = ((y_train == 0) | (y_train == 1)).ravel()
    mask_test = ((y_test == 0) | (y_test == 1)).ravel()
    X_train, y_train = X_train[mask_train], y_train[mask_train]
    X_test, y_test = X_test[mask_test], y_test[mask_test]

    # 标签已经是 0/1：1 表示数字 1，0 表示数字 0
    y_train = y_train.astype(np.float32).reshape(-1, 1)
    y_test = y_test.astype(np.float32).reshape(-1, 1)

    print(f"训练集 {X_train.shape[0]} 张，测试集 {X_test.shape[0]} 张，"
          f"每张 {X_train.shape[1]} 维（28×28）")

    # ---------- 1. 初始化参数 ----------
    n_features = X_train.shape[1]                  # 784
    W = np.zeros((n_features, 1))                  # 权重 (784,1)
    b = 0.0                                        # 偏置标量

    # ---------- 2. 训练 ----------
    lr = 0.1
    epochs = 60
    for epoch in range(epochs):
        z = X_train @ W + b                        # 前向
        y_hat = sigmoid(z)
        loss = cross_entropy(y_hat, y_train)       # 损失

        dz = y_hat - y_train                       # 反向：梯度 = 预测 - 真实
        dW = (X_train.T @ dz) / X_train.shape[0]
        db = dz.mean()

        W -= lr * dW                               # 更新
        b -= lr * db

        if epoch % 10 == 0:
            print(f"epoch {epoch:3d}  loss = {loss:.6f}")

    # ---------- 3. 评估 ----------
    y_hat_test = sigmoid(X_test @ W + b)
    pred = (y_hat_test > 0.5).astype(np.float32)
    acc = (pred == y_test).mean()
    print(f"\n测试集准确率 = {acc:.4f}  (b = {b:.4f})")

    # ---------- 4. 可视化模板 ----------
    print("\n学到的权重 W（reshape 成 28×28，越亮 = 越'像 1'的像素）：")
    show_weights(W)


if __name__ == "__main__":
    main()

7.4 八个真实的坑#

下面每一条都在这个项目里真实出现过，或者差一点就出现：

① 标签已经是 (N,1)，再加一次 [:, None] 会炸成三维

掩码之后 y 的形状是 12665×1。若顺手写成 y[:, None]，就得到 12665×1×1；此时 y^−y 仍是这个形状，但一旦与 12665×784 的输入相乘，NumPy 会把它广播成 (12665, 784, 1)——一个 990 万元素的数组，然后报 non-broadcastable output operand。

这正是我写复现脚本时踩到的第一个错误。修法不是猜，而是先 reshape(-1) 把标签压成一维，需要列向量时再显式 [:, None]，并在关键处打印 shape 核对。

② log(0) 与 eps

见 3.4 节。np.log(0) 返回 -inf，不会抛异常，只会让损失变成 nan，然后整条训练曲线看起来像「模型坏了」。加 1e-8 是成本最低的保险。

③ 原地更新要求 dtype 一致

代码里 W -= lr * dW 是原地运算。W 是 float64、dW 也是 float64，所以安全。若把 W 初始化成 float32，而 X 是 float32、y 是 float64，dW 就会被提升为 float64，此时 -= 会直接抛 Cannot cast ufunc output…。要么统一 dtype，要么写成 W = W - lr * dW（会新建数组）。

④ 准确率的广播陷阱（最隐蔽的一个）

(pred == y_test).mean() 只有在 pred 与 y_test 形状完全一致时才正确。若一边是 2115、另一边是 2115×1，比较结果会被广播成 2115×2115 的矩阵，.mean() 照样返回一个 0～1 之间的数，看起来像准确率，实际毫无意义。防御手段：比较前 ravel() 两边，或断言形状相等。

⑤ sigmoid 的溢出方向

np.exp(−z) 在 z 很负时会上溢到 inf，结果 1/(1+inf) = 0 是对的，但 NumPy 会发 RuntimeWarning: overflow。本项目的 |z| 不超过 10，碰不到；一旦不归一化像素、又把学习率调到 4，就会碰到。稳定写法是分段：z ≥ 0 用 1/(1+e^{−z})，z < 0 用 e^z/(1+e^z)。

⑥ 全批量不等于「必须一次算完」

一次前向要读 12665×784×4B≈39.7MB，这份数据放得下；换成 600 万张图就是 18 GB，必须切 mini-batch。代码里之所以能写成一整批，是数据规模允许，不是原理要求。

⑦ 学习率与归一化是绑定的

α = 0.1 之所以能直接用，前提是像素都在 [0,1]。如果把原始 0–255 的像素直接喂进去，梯度会放大 255 倍，同样的 α 会直接振荡甚至发散。这不是「调参」，是输入尺度决定了可用的步长上界。

⑧ 阈值 0.5 是一个假设，不是定理

0.5 隐含了「假阳性和假阴性代价相同」。医疗筛查、垃圾邮件、质检场景里这个假设常常不成立，阈值必须按代价重新选——见 8.6 节的实测。

8.5 概率分布：自信是好事吗#

61 张样本落在 (0.1, 0.9) 之间，占 2.9%。如果把「不确定」当成需要人工复核的信号，这个比例是可以接受的：复核 61 张就能覆盖几乎全部风险，剩下 2,054 张可以直接自动化。

但要小心：高置信度不等于高准确率。那两个错误样本的概率是 0.58 和 0.68，并不算特别高，可模型对它们的「错误」是有感知的；真正危险的是那些 p = 0.99 却判错的样本——这份数据里没有，但真实场景一定有。这也是为什么概率校准（Platt scaling、温度缩放）值得单独做一步。

09

局限与扩展#

一个 785 参数的线性模型能做到 99.91%，但它做不到的事情同样清楚。这一章说清楚边界在哪，以及下一步往哪走。

9.1 线性边界的天花板#

模型的全部表达能力，是 784 维空间里的一个超平面。它能表达「某个像素亮不亮」，表达不了「两个像素是否连通」「环是否闭合」「笔画是否交叉」。两张写歪的 0 之所以被判成 1，就是因为「斜线」这个局部特征压过了「闭环」这个全局特征——而后者根本不在假设空间里。

这不是训练不够：再多走几百步，训练损失会继续降，但那两张图的概率只会更极端地错下去。线性模型的上限由特征决定，不由优化决定。

9.2 扩展到 10 类：softmax#

把二分类的 sigmoid 换成 softmax，就得到多分类逻辑回归：每个类一个权重向量 Wk，输出归一化成概率：

pk=ezk∑j=1Kezj,zk=WkTx+bk
(21)

损失换成多类交叉熵 −yklogpk，梯度仍然是 pk−yk——同一个「预测减真实」的结构。在 MNIST 全 10 类上，这类线性模型的准确率通常停在 92% 左右（文献值），和 0/1 子集的 99.9% 形成鲜明对比：类越多、类间边界越复杂，线性假设就越吃紧。

9.3 正则化：给权重加一道约束#

Jreg=J(W,b)+λ2‖W‖2,∇WJreg=∇WJ+λW
(22)

加一项 λ2‖W‖2 相当于在每次更新时额外把权重按比例缩一点，抑制「某个像素权重过大」的过拟合。这里的 785 个参数对应 12,665 个样本，过拟合风险本来就不高，所以本文没加；但如果特征维度远大于样本数，L2 几乎是必需的。

9.4 阈值、代价与校准#

8.6 节的实验说明：阈值只改变错误在 FP / FN 之间的分配，不改变总数。真正决定阈值的是代价——漏诊一个病人和误报一次体检，代价完全不同。做法是给两类错误各赋一个代价，选使期望代价最小的阈值，而不是无脑用 0.5。

再往下一步是校准：模型的输出 0.9 是否真的意味着 90% 的把握？逻辑回归在最大似然下通常是校准得比较好的（这也是它常被用作基线的原因之一），但特征相关、样本选择偏差都会破坏这一点。

9.5 那为什么还要学它#

因为它把机器学习的每个零件都暴露在外，而且每个零件都能手算验证：

  • 凸优化：唯一最优、与初始化无关，可以把「训练失败」归因到实现而不是运气。
  • 梯度形式：ŷ − y 这个结果在 softmax、交叉熵、指数族模型里反复出现，是理解深度学习中「logits + CE」的母题。
  • 可解释：784 个权重可以直接看、可以画、可以和类均值差对比——黑箱模型做不到。
  • 基线：任何新模型都该先打败它。一个 785 参数的模型拿到 99.9%，说明这道题本身不难；换到 10 类，它就掉到 92%，差距才显出模型的价值。
