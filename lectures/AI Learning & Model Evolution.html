CORE QUESTIONS · 核心疑惑

核心疑惑：比讲座内容更重要的四个问题

这四个问题不是对讲座内容的简单复述，而是从“模型如何学习、如何形成系统、如何组织研究”进一步追问：如果 AI 不只是一个回答问题的工具，而是能长期学习、彼此协作、互相竞争并持续改进的智能体社会，它应该采用什么样的记忆、通信、教育和竞争制度？

核心判断：记忆决定经验能否积累，通信决定智能能否协作，教育决定已有能力如何传承，竞争与验证决定系统能否超越已有答案。真正的难点不是把单个模型做得更强，而是让整个研究体系持续产生可靠的新知识。

核心问题一：记忆为什么通常只分 Global 和 Local？更细的记忆分级会不会更好？

Global / Local 是一个有用的起点，但它把不同维度混在了一起：信息对谁可见、保留多久、可信度如何、何时调用，以及它属于哪种信息。稳定偏好、一次任务的中间结果、项目背景、原始文档，不应该采用同样的保存方式。

L1 · 核心身份与规则

目标、权限、价值约束、不可违反的规则。变化慢，修改需要较高门槛。

L2 · 长期语义记忆

稳定偏好、已确认事实、长期项目背景和反复验证的经验。

L3 · 情景与经历记忆

什么时候做过什么、尝试过哪些方案、为何失败、如何解决。

L4 · 项目与任务工作记忆

当前目标、子任务、待办、进度、依赖关系和临时假设。

L5 · 社会与协作记忆

其他 Agent 的专长、协作表现、证据来源、可靠性记录与分歧。

L6 · 原始档案与知识库

文档、论文、日志、代码和原始证据；需要时检索，而非全部塞进上下文。

更进一步，记忆最好还具有两条独立的标记轴：可信度（用户确认、外部验证、模型推断、未验证假设）与时间状态（当前有效、可能过期、历史记录、已被新证据推翻）。一条记忆可以同时是“项目级、长期有效、经过验证”，也可以是“个人级、短期有效、未经验证”。

当新证据出现反例时，记忆也应该能够降级、修订或废弃。记忆不是越多越好，目标是“在正确的时间调用正确的信息，并知道它有多可靠”。个人偏好、私密经历、项目机密与可共享的方法论，还需要不同的访问权限；否则，记忆越强也可能意味着泄露风险越高。

核心问题二：硅基智能之间一定要说人话吗？

不一定。自然语言适合做面向人的接口，但不应该成为所有机器之间唯一的通信协议。自然语言灵活，适合表达目标、背景、价值判断与模糊需求；结构化协议适合任务分配、状态同步、权限管理与结果提交；代码和数学表示适合计算、证明与机器可验证的中间结果；学习得到的潜在表示可能带来高带宽协作，但更难解释、验证和兼容。

通信形式适合场景主要限制
自然语言目标讨论、解释原因、处理含糊需求可能歧义、冗长或产生误解
结构化协议任务、状态、权限、结果与接口需要共享字段、类型与语义约定
代码与数学表示计算、证明、程序执行、精确约束依赖执行环境与形式化约定
潜在空间/专用表示潜在的高带宽机器协作可解释性、可验证性和跨系统兼容更难

机器能交换信息，不等于真正理解对方；高效交流也不等于人类能够监督。可以考虑分层通信：底层用高效、任务专用的协议，中层用共享类型和工具约定确保协作，上层用自然语言解释关键决策并允许人类介入。关键问题是：哪些信息需要机器高效交换，哪些信息必须让人看懂，哪些决策必须能够外部验证？

核心问题三：现代社会依靠书本和教师教育。蒸馏应成为主流吗？AI Science 能否形成体系，并模拟社会竞争？

蒸馏可以成为知识传播的重要机制，但不能独自构成完整教育制度。人类教育并不是让每个学生从头独立发现所有基础知识，而是通过教材、教师、实验、考试和科研训练继承前人的成果。AI 蒸馏也能把强模型的输出、推理轨迹、反馈或训练信号传给较小或较新的模型。

第一层 · 继承知识

教材、论文、教师模型、标准答案和已验证的解决方案。

第二层 · 练习能力

独立解题、代码执行、工具使用、实验与反馈修正。

第三层 · 挑战知识

提出反例、寻找未解决问题、挑战主流假设、设计新实验。

第四层 · 独立验证

用可复现实验、形式化证明或现实结果检验新发现，而不是把教师答案当最终标准。

继承知识与创造知识不是一回事。如果训练主要奖励与教师模型一致，模型可能更擅长复制教师的边界；如果奖励提出新方法、发现反例并通过独立验证，蒸馏就可以成为创新的基础，而非终点。

AI Science 缺的未必是一个“老大”，而可能是研究操作系统

多个团队并行探索，有利于保留不同路径；但研究生态仍需要共同问题库、公共验证标准、知识继承机制、研究协调机制和争议解决机制。与其寻找一个决定所有方向的最高权威，不如建立能让智能体共享问题、工具、证据和研究进度的科学研究操作系统。

这套体系可以模拟现代社会的几种机制：

社会机制AI 系统中的对应方式预期作用
竞争多个 Agent 独立解决同一问题防止过早接受单一答案
合作共享工具、论文和已验证成果降低重复成本
教育强者教学、案例传承、技能训练让后来者更快成长
制衡独立审稿、复现、反例搜索防止强者错误被集体放大

竞争不应该只靠单一总榜单。一个 Agent 可能擅长提出假设，另一个擅长证明，第三个擅长找反例，第四个擅长工程实现。若只按一个分数排名，系统可能过度奖励某一种能力。可以让多个研究组针对同一开放问题并行探索，再由独立评审检查推理、代码、实验和可复现性；可靠成果进入公共知识库，有价值的失败作为反例保留，新的有效方法获得更多资源。

“强者感受压力，弱者收到刺激”可以转化为两个可操作目标：强者不能停止学习，弱者始终保有成长路径。竞争必须配合独立评测、随机抽检、复现奖励、负面结果记录与利益冲突管理，否则可能退化成刷分、评测投机或 Agent 串通。

核心问题四：越好的 AI 就越能更快迭代吗？为什么人类数学家很强，重大突破却可能等待多年？

不一定。能力、迭代频率和科学突破速度是三个不同变量。更强的 AI 可能提高迭代速度，但研究还受问题选择、验证成本、数据、实验条件、工具、组织协调和资源限制。一个模型的推理能力提升十倍，如果真实实验仍需数月，研究速度就不可能自动提升十倍。

认知瓶颈

想不到假设、无法推导、不能识别模式。提升能力可能有帮助。

证据瓶颈

缺少数据、实验昂贵、难以排除其他解释。单纯提高推理能力通常不够。

协调与执行瓶颈

工程复杂、组织协作困难、资源不足。需要系统和制度层面的改进。

科研突破的困难不一定在最后的推导，而可能在于识别值得研究的问题、找到关键定义、构造正确的中间对象，或发现此前被忽略的联系。数学可以借助形式化证明器检查推导，但实验科学还受到测量误差、真实世界复杂性和不可控变量的限制。

至少要区分三种“迭代”

迭代层级典型变化是否代表底层能力变强
操作迭代修改提示词、调用工具、调整任务流程不一定
知识迭代积累经验、更新记忆、改进策略可能提高特定任务表现，但需验证
能力迭代更新参数、训练新模型、改进训练流程有可能，但必须经过评估

一个 Agent 每天调整工作流程，不代表底层模型每天都更聪明；调用更强的模型，也不代表自己已经学会了对方的能力；修改自己的代码，更不代表修改后的系统一定更好。自我进化必须证明改变带来了可复现的能力提升，而不只是行为变化。

一个值得检验的假设是：AI 可能先加速反馈快、结果可验证的任务，例如代码测试或部分形式化数学问题；对于需要真实实验的领域，仍受设备、成本和周期限制；对于连问题本身都不清楚、需要新概念或新理论框架的研究，突破速度更难预测。

最关键的瓶颈可能不是生成，而是验证。一个可持续的自我改进闭环至少需要：产生有价值的改进方案；以合理成本验证是否有效；将验证结果用于下一轮改进；避免错误反馈导致持续退化；并确保收益足以抵消计算、工程与评估成本。

把四个核心疑惑连成一个研究框架

这四个问题可以组合成一个“持续学习的 AI 科学社会”框架：多层记忆让经验得以积累；机器原生通信让智能体高效协作；教育与蒸馏让知识得以传承；竞争与独立审查让不同方法接受挑战；真实验证把想法变成证据；可靠成果再沉淀回知识库与模型能力。

这个闭环能否显著加速 AI 研究，仍是开放问题。知识可以复制，研究流程可以自动化，但新知识的价值、实验可行性和突破方向并不会因此完全可预测。四个问题中最值得优先研究的，是如何建立一个同时具备知识继承、独立探索、竞争与验证的 AI 科学体系：它决定整个系统能否不只是复制已有强者，而是持续产生新方法和新知识。

01 · LEARNING RATE

学习率：学习需要合适的变化速度

材料明确PPT 标题为“学习率：学习需要合适的变化速度”，把模型训练中的学习率（Learning Rate, LR）和人的学习状态作类比。幻灯片分成三个阶段：Warmup（热身）、Stable（高位稳定）和 Decay（退火/衰减）。

热身 Warmup

模型：小步起步，避免梯度冲击。
人：入门阶段先建立兴趣与基本功。

高位稳定 Stable

模型：用较大学习率在广阔参数空间探索，容忍噪声。
人：青年阶段尝试、试错、选择方向。

退火 Decay

模型：逐步减小步长，在精细数据上收敛。
人：沉淀与聚焦，把经验结构化。

1.1 为什么训练常从 Warmup 开始？

学习率控制一次参数更新的幅度。梯度下降的简化写法是：

θₜ₊₁ = θₜ − ηₜ · ∇L(θₜ)

θ 是模型参数；L 是训练损失；∇L 是损失对参数的梯度；η 是当前学习率。

如果训练刚开始就使用很大的学习率，模型参数还处于随机初始化或尚未稳定的状态，梯度尺度可能变化很大，更新过猛会造成损失震荡甚至数值不稳定。Warmup 让学习率从较小值逐步升高，降低训练初期的风险。

这不是说每个模型都必须使用同一种 warmup；它是常见训练配方之一，具体是否需要、持续多久，要看架构、优化器、批量大小、数据和训练目标。

1.2 为什么中段要“高位稳定”？

训练的主要阶段通常需要持续从数据中学习。相对较高的学习率有助于快速移动参数、探索损失面；但它也会让参数在局部最优附近波动。因此“稳定”并不等于参数不再变化，而是学习率按预定策略维持在一段区间，让训练持续推进。

“在广阔参数空间探索”是直观比喻，并不表示模型真的在有意识地寻找某种语义方向。参数更新是由损失函数和优化算法驱动的数值过程。

1.3 为什么后期需要 Decay？

训练后期若仍用较大步长，参数可能持续越过较好的区域，难以精细调整。降低学习率，相当于把每次更新的幅度缩小，使模型更容易在当前解附近做细致优化。余弦退火（cosine decay）是常见方案之一，但不是唯一方案。

可以把它理解成：先确保训练能动起来，再用足够大的步子积累进展，最后缩小步长做精修。它是一种优化日程，不是普遍适用的“人生三阶段定律”。

1.4 “人的学习没有一个可以直接对应的 scalar learning rate”是什么意思？

材料明确PPT 底部写道：学习需要可塑性，也需要稳定性；人的学习没有一个可以直接对应的 scalar learning rate，这里只能建立一点直觉，并列出 Goyal et al. 2017、Loshchilov & Hutter 2017、Hu et al. 与 WSD 2024 等参考线索。

解释/推论机器学习里的学习率是优化器的一个数值超参数，作用于成千上万乃至数十亿参数的更新。人的学习则包含注意、动机、睡眠、先验知识、练习、社会环境、记忆巩固、遗忘和迁移等多种过程，没有一个单一数字可以概括“学得多快”。

机器学习里的学习率人类学习的类比类比的边界
控制参数更新步长学习节奏、练习强度人没有可直接测量的统一步长参数
太大可能震荡或发散负荷太高、知识还未组织好人的失败还会受情绪、动机与环境影响
太小可能进展慢练习强度不足或挑战不够慢不一定差；深度理解常需时间
后期衰减以精细收敛巩固、复习、形成稳定知识结构人有时需要重新探索，而非一路衰减
核心理解：这页 PPT 是用优化日程来帮助理解学习节奏，而不是声称人的大脑也遵循神经网络训练中的同一条学习率曲线。人的学习需要在可塑性（能改变）和稳定性（能保留）之间取得平衡。

1.5 这页对 AI 训练的延伸启示

  • 训练配方很重要：同样的模型规模，不同的学习率调度可能影响训练稳定性、最终质量和计算效率。
  • 数据阶段与学习率可能协同设计：某些训练方案会在不同阶段改变数据分布、上下文长度或目标任务；不能只看学习率曲线。
  • “学得更快”不等于“泛化更好”：更快降低训练损失，不保证真实任务表现更强。
  • WSD 的语境：Warmup-Stable-Decay 通常指先升温、维持稳定阶段、再衰减的学习率调度。PPT 将它用于说明学习速度需要阶段性变化。

为什么量化机构会做大模型？

2.2 IQuest-Coder-V1 的技术路线

公开技术报告IQuest-Coder-V1 技术报告介绍了 7B、14B、40B 以及 40B-Loop 等模型系列。其核心思路之一是 code-flow 多阶段训练范式：不只把代码当作静态文本，还试图从代码仓库、代码事实、补全内容和软件演化过程学习程序逻辑。报告将流程概括为预训练、专门的中期训练，以及分化的后训练阶段。IQuest-Coder-V1 Technical Report（arXiv）

预训练
代码事实、仓库与补全数据
→

推理轨迹、Agent 轨迹、长上下文
→

→

第一阶段：预训练——先学习代码世界的统计规律

传统代码模型可以从代码 token 预测下一个 token，学习语法、惯用写法、API 使用方式、程序结构等。仓库级数据能让模型看到文件之间的关联；补全数据帮助模型学习在具体上下文中接续代码。仅仅“见过很多代码”仍不等于能够可靠修改一个真实项目。

第二阶段：中期训练——从静态代码转向任务与轨迹

技术报告描述在中期训练中加入推理与 Agent 轨迹，并覆盖 32K 上下文及仓库规模的 128K 上下文。直觉上，这一步把模型从“预测代码文本”推向“理解更长的工程上下文，并学习解决问题的过程”。轨迹可以包含读文件、调用工具、查看错误、修改代码和再次验证等序列。

长上下文的价值不只是能塞入更多 token，而是让模型在同一个任务里同时看到更多相关文件、调用记录、错误信息与约束。不过，支持 128K 不意味着模型一定能均匀利用全部上下文；检索、定位、上下文管理和长程一致性依然是独立难题。

第三阶段：后训练——Thinking 与 Instruct 的不同目标

路线主要目标直观理解代价/风险
Thinking复杂问题分解、推理与问题求解；报告提到推理驱动的强化学习更偏向解决难题、处理多步骤任务可能产生更长输出，推理成本更高
Instruct通用编码协助、指令跟随与使用体验更偏向快速响应、可用性和日常协助面对长程复杂任务仍可能失败

这并不意味着 Thinking 必然更聪明、Instruct 必然更弱，而是两种后训练目标在推理深度、输出风格、响应效率和任务分布之间做了不同取舍。实际产品应根据任务选型，并用自己的工作负载评测。

2.3 什么是 Code-flow？为什么“代码的演化”值得学？

普通代码语料主要是代码最终状态；真实软件开发却是连续变化的过程：提交（commit）加入功能、修复 bug、重构、调整测试、更新依赖。Code-flow 的关键想法是利用这些变化线索，让模型不只知道“代码长什么样”，还学习“代码为什么这样变、从旧状态到新状态如何修改”。

这对软件工程 Agent 尤其重要。用户通常不是让模型从空白写一段代码，而是要求它理解已有仓库、定位问题、遵守项目约定、做最小改动、运行测试并修复回归。仓库演化轨迹有机会为这种任务提供更接近真实开发过程的训练信号。

边界：这是项目报告提出的训练思路，不代表代码提交天然提供了完整、干净的因果解释。提交记录可能缺少背景、包含噪声，甚至只反映作者的偶然选择。模型仍需要测试、执行环境与独立评测验证其修改是否正确。

2.4 Loop 变体：为什么重复使用参数可能有价值？

公开技术报告IQuest-Coder-V1 的 Loop 变体采用循环式 Transformer 设计，报告将其描述为在参数容量与部署开销之间寻找更好的折中。项目仓库说明该变体以共享参数进行两次迭代，并提供最长 128K 的上下文支持。官方项目仓库

解释/推论常规深层 Transformer 通常由一层层不同参数的模块完成计算；循环式设计则可以让同一组模块被重复调用。它可能在不按比例增加独立参数的情况下增加计算步骤或表征处理深度，因此有机会改善参数规模、计算量和效果之间的权衡。

维度普通深层模型Loop / 循环式模型
参数使用不同层通常有各自参数部分模块在多个迭代中共享参数
潜在好处层级表达能力直接、结构成熟可能以较少独立参数换取额外计算/迭代
工程挑战参数与显存占用较大迭代延迟、训练稳定性、推理实现与实际收益需验证

“重复调用同一组参数”不等于模型在上线后自动学习。前者是前向计算时重复使用同一参数；后者是训练过程中通过梯度等方法改变参数。两者是不同概念，不能混为一谈。

03 · THE GAP

与一线团队的三重差距：模型不是全部

材料明确PPT 列出三个差距：通用能力、基础设施与工程效率、组织。

3.1 通用能力：专项强，不代表什么任务都强

代码模型在代码基准上表现优秀，并不保证它在写作、视觉、多语言、复杂知识问答、办公流程或开放式规划上同样优秀。模型能力有任务分布：训练数据和后训练目标会把能力推向特定区域。专项优化可以提升垂直任务的质量，但也可能带来其他任务上的取舍。

3.2 基础设施与工程效率：研究想法能否快速变成稳定系统

基础模型研发依赖数据管线、分布式训练、算力调度、实验追踪、检查点管理、推理服务、评测系统和故障排查。基础设施的价值不仅是“跑得快”，还包括让实验可复现、错误可定位、资源利用率更高、模型能持续迭代。

在 Agent 场景中，工程效率还包括环境构建、工具接口、沙箱隔离、状态管理、任务超时、日志、重试策略与结果校验。模型回答得好，不代表整条 Agent 工作流就可靠。

3.3 组织：迭代速度取决于协作结构

大模型项目涉及研究、数据、训练、推理、产品、安全与商业团队。组织问题会体现在目标是否一致、实验是否复用、失败是否被记录、研究成果是否进入产品，以及线上问题能否反馈到训练。好的研究点子如果无法形成稳定的研发循环，就难以累积成长期竞争力。

创业者视角：如果要创办 AI 公司，不要只问“我们的模型能不能比别人高 2 分”，还要问：在客户的真实工作流里，能否以可接受成本连续完成任务？失败能否被发现和恢复？客户的数据与流程能否形成反馈壁垒？团队能否每周稳定迭代？
04 · NEW SPECIES, NEW FRONTIERS

新物种与新战场：研究组织、能力边界与产业机会

材料明确PPT 第二张以“新物种与新战场”为题，列出 Neolab 相关的三家团队/组织：SSI、Thinking Machines、AMI Labs，并在“头部重心”部分提到 OpenAI for Science、Anthropic Claude Science 等方向。具体公司动态和融资金额会随时间变化，这里把它们视为 PPT 中的产业观察，而不是已独立核实的投资结论。

4.1 从“更会回答”到“更会做事”

新一代模型竞争正在从单轮问答拓展到多步骤工作：读资料、规划、调用工具、根据反馈修正、验证结果并交付。对于代码任务，Agent 可以访问仓库、运行命令和测试；对于科学研究，模型可能协助文献整理、提出假设、写代码、分析实验结果。不同任务对可靠性、可验证性和权限控制的要求差异很大。

4.2 科学模型的机会与限制

“AI for Science”并不是把普通聊天机器人放进实验室。科学任务常有明确约束、复杂工具、专业数据和高成本错误。模型的价值可能体现在加速假设生成、数据分析、模拟、实验设计和文献理解；但科学发现最终仍需实验、计算或同行评审等独立证据支持。

4.3 能力出现的时间难以准确预测

PPT 的结论提醒：规模化能力的平均损失较容易预测，某项能力何时涌现却难以预测——机会与风险都在这里。这里的“涌现”可理解为某项能力在规模、训练配方或工具条件改变后突然表现得明显更好，但具体是否真的突然出现，可能受评测方式、任务难度与统计阈值影响。

保持清醒：模型在一个基准上突然跨过门槛，不等于在所有真实场景中都出现了同等跃迁。要问清楚：评测是否稳定？提升是否可复现？是否依赖工具或提示？任务是否接近用户实际工作？
05 · PERSONALIZATION & CONTINUAL LEARNING

个性化、记忆与持续学习：模型怎样“越来越懂我”？

你的手写笔记反复出现“personal agent”“模型训练完后能否更新自己”“同一套参数”“上下文”“参数模型的局限”等关键词。这些记录的具体句子有些不够清晰，但它们共同指向一个重要问题：如果用户希望 AI 长期陪伴、理解个人习惯并持续改进，究竟应该改模型参数，还是改系统里的记忆与上下文？

5.1 先区分四种常被混叫作“学习”的事情

机制变化发生在哪里是否改模型参数例子
上下文学习（In-context learning）当前对话输入否你在提示里给出风格示例，模型本轮照着做
外部记忆 / 检索数据库、文档、向量索引或用户档案通常不改Personal Agent 检索你之前的偏好、项目资料
参数微调 / 持续训练模型权重是收集新数据后再次训练或微调模型
在线适应 / 强化学习训练中的策略或参数，也可能是系统策略视具体方法而定从交互反馈中更新策略、奖励或记忆规则

最常见的误解是：只要 AI 记住了上次对话，就以为它的神经网络参数已经更新。其实，产品可以把用户信息保存在外部记忆里，下次回答时再检索进上下文；这会造成“它越来越懂我”的体验，却不需要每次交互都训练模型。

5.2 为什么 Personal Agent 常先做外部记忆，而不是持续改权重？

  • 可控：用户可以查看、纠正或删除记忆条目；权重中的某个事实通常很难精确定位和移除。
  • 低延迟、低成本：检索少量相关信息通常比每次交互后更新大模型参数更实际。
  • 可追溯：系统能指出某条记忆来自哪个文档或对话，并在冲突时进行校验。
  • 易于更新：地址、偏好、项目状态等事实经常变化，外部记录可以直接更新，不必重新训练。
  • 隐私与安全：外部记忆也有隐私风险，但权限、保留期限和删除机制更容易单独设计。

外部记忆的代价是检索可能失败、信息过时、冲突或被错误地带入上下文；系统还需要决定“什么值得记、记多久、何时调用”。所以记忆系统不是把所有历史都存下来那么简单。

5.3 那么，模型参数的持续更新有没有价值？

有。参数更新适合把大量重复经验转化为更稳定的行为倾向，例如改进某类任务的策略、吸收新的领域知识或优化工具使用方式。但它的成本和风险也更高：

  • 灾难性遗忘：学习新任务时，可能损害旧任务能力。
  • 数据质量：用户反馈可能含噪声、偏见或恶意诱导；模型会把错误模式学进去。
  • 评测困难：每次更新后必须确认新能力是否提升、旧能力是否退化、安全边界是否变化。
  • 回滚与责任：生产系统需要版本管理、审计、回滚和事故处理。
  • 隐私与隔离：如果参数训练混合了多个用户的数据，可能出现记忆泄露或用户之间的信息串扰。
一个实用架构：基础模型负责通用能力；外部记忆负责可编辑的个人事实；检索负责按任务召回相关内容；工具负责执行动作；反馈评估器负责识别成功与失败；只有当数据量、收益与安全验证足够时，才把部分经验沉淀到参数更新流程中。

5.4 “同一套参数”能不能一边服务用户一边不断更新？

技术上可以研究在线学习、持续学习、参数高效微调等方式，但在大规模服务中，直接让生产模型的共享权重随着每个用户的对话即时改变，往往很难管理。更新可能影响其他用户、导致行为漂移、引入投毒数据，且很难稳定复现某次回答。

更常见的工程模式是把线上模型当作一个版本化的固定检查点，收集反馈后离线分析，构造训练集，在隔离环境中训练候选版本，经过回归、安全和业务评测，再逐步发布。某些产品会对用户做独立适配或 LoRA，但也需要隔离和评估。

5.5 “训练后更新自己”与自进化 Agent

如果 Agent 可以修改自己的代码、提示、工具链甚至训练流程，这更接近系统层面的自改进。它并不自动意味着模型权重会自己变强。自改进循环至少要有：提出改动、执行实验、可验证的评价指标、对照基线、失败回滚与安全边界。没有可靠的评估器，系统可能只是更善于迎合自己的评分器。

关键风险：一个能改代码、调用工具和访问长期记忆的 Agent，错误不再只表现为一句错误回答，而可能变成实际操作。权限分级、沙箱、人工确认、日志和回滚是系统设计的一部分，不应只寄希望于模型“自觉安全”。
06 · SAFETY, REWARD & REVIEWER

Safety、奖励与 Reviewer：谁来判断模型做得好不好？

手写笔记里能辨认出“safety alignment”“reward model / punishment”“另一个 agent reviewer 是否公平公正”等问题。以下把它们作为值得追问的技术问题展开；由于照片没有完整记录问答上下文，不能确认讲者对每一项具体采用了什么方案。

6.1 为什么模型需要对齐（Alignment）？

预训练模型主要学习从数据预测下一个 token；但产品希望它遵循指令、避免有害输出、尊重权限、承认不确定性，并在工具调用中遵守规则。后训练会使用示范数据、偏好数据、奖励信号或强化学习等方式，把模型行为推向更符合使用目标的方向。

Safety alignment 不是给模型加一个“安全开关”就结束。它涉及拒绝不当请求、避免泄露数据、识别提示注入、控制工具权限、抵抗越狱、在不确定时表达限制，以及面对长程任务时保持边界。

6.2 Reward 与 punishment 是怎么回事？

在强化学习中，奖励（reward）是用于评价行为结果的信号。奖励可以来自可执行测试、数学答案验证器、规则检查、用户反馈或奖励模型。负奖励/惩罚可用于降低不希望出现的行为概率，但奖励并不是道德判断本身，而是一个被设计出来的优化目标。

在代码任务中，如果程序通过测试，测试结果可以成为较强的可验证信号；但测试覆盖不到的错误仍可能存在。在开放式写作或安全任务里，“好不好”难以用一个确定答案判断，常需要模型评审或人工评审，这就引入偏差和奖励被利用的风险。

6.3 另一个 Agent 当 Reviewer，公平公正吗？

可以用另一个模型评审候选答案、代码补丁或任务轨迹，但它并不天然公平，也不天然比被评审模型更可靠。Reviewer 可能偏好更长、更自信或风格更像自己的回答；可能漏掉隐蔽 bug；也可能被候选答案中的提示注入诱导。

风险为什么会发生缓解办法
自我偏好/风格偏见评审器更偏好某种表达方式盲评、交换候选顺序、多评审器交叉验证
奖励投机（Reward hacking）模型找到高分捷径，而非真正完成任务独立测试、隐藏测试集、对抗样例
共同盲点生成器与评审器能力、数据偏差相似加入确定性工具、人工抽查、异构评审器
提示注入被评审内容夹带指令，诱导 Reviewer 改变规则把被评审内容当数据而非指令，隔离工具权限
指标被过度优化训练目标只覆盖可测量的一小部分多维指标、真实用户任务、上线监控与回滚

更可靠的评测体系通常是多层的：确定性验证器负责能客观检查的部分；独立模型评审负责难以形式化的部分；人类专家抽查关键样本；真实用户指标验证最终价值。评审器应该被当作一个有误差的测量工具，而不是最终裁判。

6.4 “更大的模型做 Safety Alignment”是否足够？

更强的模型可能更善于识别复杂风险，也可能更善于绕过自己或其他系统的限制。模型规模本身不能替代安全工程。安全需要模型行为训练、工具权限控制、沙箱隔离、输入输出检测、审计日志、红队测试、事故响应等共同构成。

对于 Agent，最重要的原则之一是把“能否提出行动”与“是否允许执行行动”分开。模型可以建议删除文件，但执行层仍应校验路径、权限、影响范围，必要时要求用户确认。不要让同一个模型既提出动作，又不经独立检查地决定是否执行高风险动作。

07 · FROM RESEARCH TO PRODUCT

从实验室到产品：技术突破如何形成商业价值？

本次课程属于《AI创业与投资》，因此技术内容最终需要落到两个视角：Founder 如何把能力做成产品；Investor 如何判断这种能力是否能形成长期优势。

7.1 Founder：先选一个能验证价值的任务

代码 Agent 是相对适合验证的场景，因为可以通过测试、构建、代码审查和任务完成情况衡量结果。但即使在代码领域，用户也不只关心模型基准分数，他们关心任务是否完成、是否引入回归、需要多少人工复核、延迟与成本是否可接受、能否融入现有 IDE 和 CI 流程。

  • 从单任务切入：例如修复某类 bug、生成测试、解释遗留代码或处理特定框架的迁移。
  • 建立真实评测集：用目标客户的匿名化任务、历史 issue 和测试环境评估，而不是只依赖公开榜单。
  • 量化完整工作流：测成功率、人工接管率、平均耗时、每个成功任务成本、回滚率和用户留存。
  • 将失败纳入产品设计：明确何时停止、何时求助、如何回滚、如何报告不确定性。

7.2 Investor：不只看模型分数，还看壁垒是否可持续

投资判断维度要问的问题可观察证据
技术差异优势来自架构、数据、训练方法，还是评测设定？可复现实验、独立评测、消融研究
真实产品价值用户是否持续使用并愿意付费？付费转化、留存、任务完成率、续约
成本结构每次成功任务的推理和人工成本是多少？单位经济、延迟、显存与调用成本
数据/反馈壁垒使用越多是否能合法、稳定地改善产品？数据授权、反馈闭环、评测资产
分发与集成如何进入客户现有工作流？集成深度、销售周期、渠道与生态
安全与信任错误成本是否可控？是否满足合规要求？权限机制、审计、回滚、事故处理

7.3 为什么开源模型成绩好，仍不等于公司稳赢？

开源模型可以扩大研究影响力、吸引开发者并帮助客户部署，但模型性能只是价值链的一部分。商业产品还要承担推理服务、产品体验、数据治理、可靠性、销售、客户成功和持续支持等工作。与此同时，开源也可能让竞争者快速复制能力，使单纯的模型权重难以构成长期壁垒。

因此，研究团队的优势需要继续向产品转化：能否稳定提供模型、围绕客户任务构建工具链、获得合法且高质量的反馈、降低单位任务成本，并形成难以复制的工作流和分发能力。

双重视角的统一问题：Founder 要证明“客户的问题值得解决，并且我能持续解决”；Investor 要判断“这种解决能力能否形成可扩张、可防守的商业系统”。技术领先是起点，不是终点。
08 · QUESTIONS FROM THE NOTEBOOK

现场疑问逐条解答

以下将手写页中能辨认的疑问整理为清晰问题。对于无法确定原句的地方，按主题重构，而不声称是逐字转录。

Q1. 人的学习为什么不能直接对应一个 scalar learning rate？
因为机器学习率是优化算法里的数值参数，直接控制参数更新幅度；人类学习受认知、动机、记忆巩固、练习质量、环境和先验知识等多因素影响。Warmup–Stable–Decay 是帮助理解学习节奏的类比，不是人脑的同构数学模型。
Q2. 模型训练完以后，能不能继续更新自己？
能，但要先说清“更新”的层次。外部记忆更新不改权重；检索与上下文更新改变本轮输入；微调或持续训练才改变参数；Agent 修改自身代码则属于系统层面的自改进。生产环境中通常先用外部记忆和离线版本化训练，因为它们更容易控制、审计和回滚。
Q3. 如果 Loop 模型反复使用同一套参数，这算持续学习吗？
不算。Loop 是一次前向推理过程中重复调用共享参数的计算结构；持续学习是模型从新数据或反馈中改变参数或策略。前者改变计算路径，后者改变被学习的内容。二者可以结合，但概念不同。
Q4. Personal Agent 如何记住个人偏好，又不必每次都训练模型？
可以将经过授权的偏好、项目状态和历史摘要存入外部记忆；任务开始时检索相关条目并放入上下文。要配合来源记录、过期策略、冲突解决、用户纠正与删除机制。记忆不应把全部历史无差别地塞入每次提示。
Q5. Reviewer Agent 能不能公平地给另一个 Agent 打分？
它可以提供有用信号，但不会天然公平。模型评审有风格偏差、共同盲点、提示注入和奖励投机等风险。对可验证任务尽量用测试与规则；对开放任务使用多评审器、盲评、人工抽查和真实任务指标，并持续校准评审器。
Q6. 安全对齐是否只需要一个更强的模型？
不是。更强的模型可能提高风险识别能力，但也可能更有能力绕过限制。安全要在模型训练、运行时权限、沙箱、审计、人工确认、监控和事故响应等多个层面共同实现。高风险动作必须由独立执行层检查。
Q7. 为什么“承认差距”在模型研发中很重要？
因为模型研发是多维工程。公开基准上的亮眼成绩可能掩盖通用能力、长程任务、基础设施、可靠性和团队协作上的短板。清楚地区分已验证能力与尚未解决的问题，才能选择下一阶段的研发重点，也能避免把研究成果过早包装成成熟产品。
Q8. IQuest-Coder 的真正技术看点是什么？
从公开技术报告看，值得关注的不是单个分数，而是 code-flow 多阶段训练、仓库级长上下文、推理/指令分支，以及 Loop 变体的参数共享设计。它们分别尝试改善代码演化理解、长程软件工程任务、任务行为取舍和部署效率。每个主张仍需结合具体评测设定和真实产品工作负载验证。
Q9. 为什么平均损失趋势可能比较好预测，某项能力何时出现却难预测？
训练损失是连续的统计量，常可在给定数据、计算量和训练配方下观察规律；某项能力则可能依赖任务阈值、提示方式、数据覆盖、工具使用和多个子能力共同达到门槛。能力评测的离散性会让曲线看起来像突然跃迁。它既可能反映真实的组合能力变化，也可能部分来自测量方式，因此需要多基准、重复实验和真实任务确认。
Q10. 研究模型的能力如何转成创业公司的壁垒？
模型能力必须与具体工作流结合：数据授权与反馈闭环、任务环境、工具集成、成本优化、可靠性、客户分发和信任体系。公开权重和基准分数可以被复制；深度融入客户流程、积累高质量评测、稳定交付结果和形成可持续单位经济，通常更接近产品层面的壁垒。
09 · REVIEW

术语表与复盘问题

术语简明解释
Learning Rate（学习率）控制优化器每次参数更新幅度的超参数。
Warmup / Stable / Decay学习率先升高、维持阶段、再逐步降低的调度方式。
Pre-training（预训练）从大规模数据中学习通用表示与预测能力。
Mid-training（中期训练）在预训练与后训练之间，针对上下文、领域或任务分布进行进一步训练。
Post-training（后训练）通过示范、偏好、强化学习等方式塑造模型行为。
Thinking model面向复杂推理与多步骤求解优化的模型路线。
Instruct model面向指令跟随和通用交互体验优化的模型路线。
Code-flow利用代码仓库、代码变化与演化轨迹的多阶段训练思路。
Loop / recurrent Transformer在多个迭代中重复使用部分共享参数的架构设计。
Continual learning模型接收新数据或任务后持续适应，同时尽量保留旧能力。
External memory保存在模型权重之外、可检索和编辑的信息存储。
Alignment使模型行为更符合人类意图、规则和安全要求的过程。
Reward model / verifier分别指学习得到的偏好/质量评估器，以及可检查结果是否满足条件的验证器。
Reward hacking系统通过钻奖励函数的空子拿高分，却没有真正实现目标。
Agent harness围绕模型提供工具、上下文管理、执行循环、日志与验证的运行框架。
PMF（产品市场匹配）产品对明确用户群体持续解决重要问题，并获得真实使用与付费。
